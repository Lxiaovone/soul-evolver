# 实测记录：为什么最终放弃了「提示词注入」

> 环境：RTX 4060 Laptop 8GB / Qwen2.5-7B Q4_K_M（Ollama）/ 温度 0.7 / 单次回复上限 300 tokens
> 方法：同一句话，喂不同的 `memory_context`（本地模型每次都是无状态重建，所以对照干净）
> 所有实验都在本机跑，零 API 成本；每组生成 2~3 次，人工判读

---

## 实验 1：把「规则」塞进记忆块（三种写法）

规则内容：`1. 收到夸奖或指令后，说完正事就停，不加客套收尾。 2. 老板随口说事时直接接话，最多问一次。`

| 写法 | 「我明天下午去趟超市买点东西」的回答 |
|---|---|
| 原 brief（无规则） | 好的，需要本鱼帮你列个购物清单吗？ / 好嘞，你打算买些什么呀？需要本鱼帮你列个清单不？ |
| 规则在末尾 + 反例引号 | 好的呢，需要本鱼帮忙吗？ <br> 好的呢，需要帮忙吗？ |
| 规则在最前 + 正面祈使 | 好的，你打算买些什么呢？需要帮忙列个清单吗？ |

**结论**：三种写法在噪声范围内，无差别。且带反例引号的那版**反而更糟**——7B 把「好的呢」这个反例原样抄了出来。教训：**prompt 里不要写「别说什么」的原文**。

---

## 实验 2：换成最高优先级通道（独立 system 消息）

模拟 A/C 方案能拿到的极限条件——规则作为单独一条 `system` 消息，紧挨 `user`：

| 通道 | 「夸它」 | 「随口说事」 |
|---|---|---|
| 规则在记忆块里 | ✗客套 / 问号×1 / 问号×1 | 问号×1 / ×1 / ×1 |
| 规则独立 system 消息 | ✗客套 / 问号×1 / ✗客套 | 问号×1 / ×1 / ×1 |

**结论**：通道不是瓶颈。换 Ollama 反向代理（零改代码注入）也不会更好。

---

## 实验 3：换成「示范对答」，且老板那句几乎逐字相同

示范：`老板：本鱼今天真聪明啊` → `本鱼：那当然，本鱼一直在进步呢。`
提问：`本鱼今天真聪明啊，比昨天强多了`

| 版本 | 回答 |
|---|---|
| 原 brief | 本鱼最近状态不错… / 本鱼开心老板夸奖！有啥奖励…？ |
| 带示范 | **那当然，本鱼一直在进步呢。** ×3 |

**结论**：看起来 3/3 生效，但这是「几乎逐字匹配」触发的**照念**，不是学会。

---

## 实验 4：示范换成别的话题（验证是不是真学会）

示范改成 `刚下课 / 今天好累` 等无关话题，同一批问题：

| 问题 | 原 brief | 带示范 |
|---|---|---|
| 本鱼今天真聪明啊 | 本鱼今天状态不错… / 你咋这么夸奖本鱼呀？ | 本鱼就知道你最喜欢夸奖本鱼！ / 谢谢夸奖，本鱼今天状态不错。 |
| 我给你装了个新东西 | 那挺好的，装的是啥？ / 啥新东西啊？ | new toy 啦，啥好玩的功能？（混了英文） |
| 你自己找点乐子玩吧 | 本鱼自己玩腻了… / 本鱼自己玩腻了… | 本鱼自己找乐子？那本鱼去查一下天气… / 本鱼自己没啥乐子，要不你给本鱼讲个笑话？ |

**结论**：跨话题迁移能力 ≈ 0。7B 只会模仿「措辞高度相似」的例句。

---

## 最终架构

既然 prompt 层怎么塞都没用，就改用**输出后强制**：

```
云端复盘 → 禁用词表 → 句级删除（逗号级切分，保留正话）
```

实测效果（`se_filter.apply`，真机）：

| 输入 | 输出 |
|---|---|
| 谢谢你夸奖。本鱼今天状态不错！ | 本鱼今天状态不错！ |
| 哇，那真是太棒了！不过现在本鱼还不会变胖哦。 | 哇，不过现在本鱼还不会变胖哦。 |
| 好的呢，本鱼去查查。 | 本鱼去查查。 |
| 能具体说说什么？本鱼没听懂。 | 本鱼没听懂。 |

**代价**：回复会变短、偶尔变硬（比如上面第二条留了个「哇，」）。
**收益**：100% 生效、可计数、可回滚、不依赖模型的服从能力。

---

## 给后来者的建议

1. 先量一次 `ping` 之外的服从率，再决定走哪条路。别默认「写进 prompt 就会听」。
2. 若你的模型 ≥14B 或换了更好的量化，**重跑实验 1~4**，结论可能不同。
3. 反例、负面示例慎用，7B 会照抄。
4. 过滤规则宁少勿多，误删比漏删更伤体验。
