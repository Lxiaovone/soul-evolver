# SE（Soul-Evolver）· 让本地 7B 越聊越像人的外挂

> 一个**不改主程序核心逻辑**的外部模块：每天用云端大模型复盘聊天记录，自动生成「症状 → 禁用词」规则，
> 再由一个 190 行的过滤门在输出后执行。适合「本地 7B 便宜但不像人，云端聪明但费钱」的场景。

- 主程序改动：**7 行**（带标记，删掉即回滚）
- 常驻进程：**0 个**（每天一个 5 秒的批处理）
- 每轮对话开销：**≈0.02 ms**（mtime 比较 + 字典查表）
- 每次复盘花费：**1~4 分钱**（DeepSeek，3000~4000 tokens）

---

## 一、为什么不是「往 prompt 里塞规则」

这是本项目的核心结论，也是它和同类做法的区别。在 8GB 显存笔记本 + Qwen2.5-7B(Q4) 上实测：

| 实验 | 手段 | 结果 |
|---|---|---|
| 1 | 抽象规则（「别客套收尾」），三种写法 | 服从率 ≈ 0，和没注入无差别 |
| 2 | 规则改成**独立 system 消息**（最高优先级通道） | 仍然 ≈ 0 |
| 3 | 示范对答，且「老板」那句和测试问题几乎逐字相同 | 3/3 生效——但那是**照念**，不是学会 |
| 4 | 示范对答，换话题 | 不稳定，甚至带出英文碎片 |

结论：**7B 没有跨话题的行为修正能力，prompt 层怎么塞都不行。**
真正 100% 生效的是**代码层句级过滤**——这和「酒句删不掉就写个正则删」是同一个思路。

所以 SE 的产出不是「给模型的补丁」，而是**给代码的删句表**。

## 二、它怎么工作

```
23:00  ① 复盘：读当天对话 → 云端 API → JSON{症状, 示范, 禁用词, 证据}
                    ↓
       ② 落库：persona_rules.json（症状-禁用词字典，永久沉淀；治不好就 fail_count+1、换说法）
                    ↓
       ③ 执行：se_filter.apply() 在输出后把含禁用词的**小句**删掉（逗号级切分，保留正话）
                    ↓
       ④ 观测：se_hits.log 记录每一次命中（行数=命中数），可量化
```

示例规则：

```json
{
  "id": "R002",
  "症状": "空话敷衍，用感叹词撑场面",
  "示范": [{"老板": "给你装个新东西", "本鱼": "装啥？说清楚点本鱼才懂。"}],
  "禁用词": ["哇，那真是太棒了", "好的呢"],
  "证据": "哇，那真是太棒了！不过现在本鱼还不会变胖哦。",
  "fail_count": 0, "status": "启用"
}
```

实际效果：

| 模型原话 | 过滤后 |
|---|---|
| 谢谢你夸奖。本鱼今天状态不错！ | 本鱼今天状态不错！ |
| 好的呢，本鱼去查查。 | 本鱼去查查。 |
| 能具体说说吗？本鱼没听懂。 | 本鱼没听懂。 |

## 三、安装（3 步）

### 第 1 步：放文件

```
你的主程序目录/
├── main.py
├── se_filter.py          ← 从本仓库拷
└── SE/                   ← 从本仓库拷
    ├── evolve.py
    ├── evolve_config.json        （用 evolve_config.example.json 改名）
    └── persona_rules.json        （可空着，或用 persona_rules.example.json）
```

`evolve.py` 默认把「自己所在目录的上级」当成主程序目录（也支持环境变量 `FEISHU_BOT_HOME` 覆盖）。
`se_filter.py` 默认读 `SE/persona_rules.json`（也支持 `SE_RULES_PATH` 覆盖）。

### 第 2 步：在主程序输出口加 7 行

找到你所有对外文本都要经过的那个函数（本项目示例是 `_output_gate`），在 `return` 前插入：

```python
# --- SE-FILTER-BEGIN（删掉本段即回滚；SE 目录不存在时自动跳过）---
try:
    import se_filter
    text = se_filter.apply(text)      # 变量名按你的函数改
except Exception:
    pass
# --- SE-FILTER-END ---
```

要点：**异常必须吞掉**。宁可漏洗，不能把回复吞了。

### 第 3 步：加计划任务

```bat
schtasks /create /tn "SE复盘" /tr "D:\你的目录\SE\se_review.bat" /sc DAILY /st 23:00 /f
```

`se_review.bat` 内容（**必须纯 ASCII**，cmd 按 ANSI 读，中文注释会让它崩）：

```bat
@echo off
set PY=D:\你的目录\.venv\Scripts\python.exe
set SE=D:\你的目录\SE\evolve.py
"%PY%" "%SE%" --review >> "D:\你的目录\SE\se_task.log" 2>&1
```

**不需要重启主程序**：`se_filter` 按 mtime 热加载，写完规则下一条回复就生效。

## 四、配置（`SE/evolve_config.json`）

| 键 | 说明 |
|---|---|
| `stage` | `fast`=每天复盘（前期定型）；`stable`=每 7 天（后期微调） |
| `trigger_time` | 自动复盘时间（配合任务计划用） |
| `review.min_turns` | 当天至少聊几句才复盘（默认 6，太少没意义） |
| `review.max_new_rules` | 一次最多产几条（默认 3） |
| `review.log_candidates` | 主程序日志候选名（只在读不到记忆实体时兜底用） |
| `inject.enabled` | **已废弃**（brief 注入路线，实测无效，默认 false） |
| `api.max_calls_per_day` | 每天最多调几次 API（硬闸，默认 2） |
| `rules.forbid_patterns` | 人设铁律正则：解药/示范撞上就丢弃（防止 AI 建议你改掉角色自称） |

## 五、指令通道（可选，飞书为例）

不接指令也能用（纯定时）。想「随时手动催一次」，可以让模块自己轮询记忆库：

1. 把 `se_watch.bat` 放进计划任务，**每 2 分钟**跑一次（内部有时段守卫，晚上不跑）
2. 主程序会把你说的话存成记忆实体，SE 扫到关键词就自己动手，然后**自己调飞书 API 回你**

支持：`立即进化` / `撤销进化` / `看规则`（同义词见 `CMD_WORDS`）。

主程序完全不知道这件事，也不会被阻塞。

## 六、回滚（三种粒度）

| 粒度 | 操作 |
|---|---|
| 只停过滤 | 把规则 `status` 改 `弃用`，或清空 `禁用词` |
| 撤钩子 | 删掉那 7 行标记块 |
| 全撤 | `schtasks /delete /tn "SE复盘" /f` + 删 `SE/` 目录（钩子自动空转） |

## 七、已知限制（诚实清单）

1. **数据源耦合**：`collect_today()` 默认读 `<bot_home>/Mem_Data/mem_*.txt`（V6 记忆实体，含 `老板：/小肥鱼：` 双边）。
   你的主程序结构不同就改这里约 40 行，或设 `SE_MEM_DIR` 指向你自己的存储。
2. **角色词写死**：prompt 与护栏里用了示例角色「本鱼 / 老板」。换角色请全局替换（共约 20 处，主要在三段 prompt 和 `forbid_patterns`）。
3. **禁用词会误删**：删的是「含该短语的小句」，可能让回复变短变硬。所以有 `max_rules`、`max_chars` 上限和 `fail_count` 淘汰机制；`se_hits.log` 可以事后核对。
4. **API 可能返回非 JSON**：三级修复（整体解析 → 去代码围栏 → 括号配对扫描）后仍失败则**不写库**，规则库保持原样。
5. **上游模型换了就不是这套结论了**：本文的「注入无效」是 7B-Q4 的实测，14B 以上未必。
